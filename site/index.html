Works where you already work

One server for terminal agents, VS Code and NetBeans, on Windows, macOS and Linux; CI runs the end-to-end smoke test on all three.

What your agent gets

Thirteen tools, addressed by symbol, not by cursor position. The agent keeps editing files itself; the server answers what text search cannot and makes the changes that are error-prone as text edits.

  • Refactor

    Rename, move, change a signature, safe delete and inline, for every caller and override. Written to disk and returned as one unified diff, and checked for new compile errors, also in files the change did not touch.

    rename symbol: com.acme.Foo#bar(String)  new_name: send

  • Migrate

    Structural search and replace with NetBeans' Jackpot rules: matches types, not text, with a dry run first. Tested packs for JUnit 4 to 5, javax to jakarta and Java modernization.

    apply_rule pack: jakarta

  • Debug

    Runs a JUnit test under the debugger and stops once, at a method, a line or a thrown exception. Returns the stack, the locals and the values of given expressions, instead of a println loop.

    debug stop_at: com.acme.Billing#total()

  • Navigate

    Semantic usages, grouped by file or by calling method; implementations with the override chain; outlines of your types and of the JDK and dependency APIs.

    find_usages symbol: com.acme.Foo#bar(String)  group_by: caller

  • Check

    Compile errors of given files or the whole workspace, without a build.

    diagnostics

  • Review and stay in control

    In VS Code every refactoring shows with Review (a multi-file diff) and Undo. Writes stay inside the workspace unless you allow a folder.

    public static String getShortClassName(Class<?> cls)
    public static String shortClassName(Class<?> cls)

How it works

  1. Your agent · Claude Code, Copilot, Codex, Cursor …
  2. ↓ mcp over stdio
  3. dukehoff-mcp launcher · connects to the workspace's server
  4. ↓ local socket
  5. Headless Apache NetBeans · one per workspace, its index kept warm between sessions; in VS Code or NetBeans the IDE's own
  6. ↓ reads and refactors
  7. Your Maven, Gradle or Ant project

Everything runs on your machine: no account, no cloud index. No code leaves the computer apart from what your agent itself sends to its model.

Where it doesn't help

  • Everyday tasks. A small feature, a bug fix, a new test: agents do as well without it. In 27 such sessions with the server offered, they made no call and paid nothing extra.
  • Agents need a nudge. They pick the tools reliably once your CLAUDE.md or AGENTS.md has a short section; the VS Code extension offers it.
  • First start of a large project. Indexing takes minutes, about 6.5 for 584 Maven modules; after that the index stays warm.
  • Java only. No Kotlin.

Install

VS Code and NetBeans bring the server along. For terminal agents, download the runtime from the releases (about 270 MB; needs a JDK 17 or newer).

VS Code + GitHub Copilot

Install Dukehoff MCP for Java from the Marketplace. It brings the Apache NetBeans Language Server along; the tools appear in Copilot's agent mode as the server java.

code --install-extension dukehoff.dukehoff-mcp-java

Claude Code

Unpack the runtime, then register it:

tar xzf dukehoff-mcp-<version>.tar.gz -C /opt
claude mcp add --scope user java -- /opt/dukehoffmcp/bin/dukehoff-mcp

GitHub Copilot CLI

Add the runtime to ~/.copilot/mcp-config.json, then start copilot in your project:

{ "mcpServers": { "java": { "type": "local",
    "command": "/opt/dukehoffmcp/bin/dukehoff-mcp", "args": [], "tools": ["*"] } } }

Codex CLI

Add the runtime to ~/.codex/config.toml:

[mcp_servers.java]
command = "/opt/dukehoffmcp/bin/dukehoff-mcp"
args = []
startup_timeout_sec = 120

Apache NetBeans

Install the plugin from the releases in NetBeans 31 or newer (Tools › Plugins › Downloaded), then let a terminal agent use the running IDE:

java -jar dukehoff-mcp-launcher-<version>.jar --config claude --ide
